- 修复的两个 bug：时长分段选择被默认值覆盖；跟练完成页会破坏二次跟练（改为叠加 overlay）。
- 验证：所有 JS node --check 通过；AI 逻辑 node 实测（搜索/计划/卡路里/BMI）正常；http 各资源 200。

## 把 PWA 做成真正 APK（Capacitor 原生工程）
- 用户要求「帮我做成APK」。环境探测：无 JDK / 无 Android SDK / 无 Gradle，但 npm registry 可达、app 用相对路径（WebView 安全）。
- 用 Capacitor v7 把 `fitness-app/` 包成原生 Android 工程：`npm i @capacitor/cli @capacitor/core @capacitor/android` → `npx cap add android`。
- 修复 cap 生成时的包名错配（java 文件在 com/fitcheck/app 但 package 声明仍是 com.getcapacitor.myapp）与缺失的 `colors.xml`：
  - 新建 `res/values/colors.xml`（colorPrimary #12b76a 等）。
  - MainActivity package、build.gradle namespace/applicationId 改为 `com.fitcheck.app`；strings.xml app_name=健身打卡。
  - 移除 INTERNET 权限（纯本地/离线）。
  - 品牌图标：用 Pillow 生成各密度 launcher（绿→蓝渐变+哑铃）+ 重绘 adaptive 矢量 + 替换 11 个 splash.png（gen_icons.py）。
- `npx cap sync android` 把 Web 资源（含 128MB GIF）拷入 `android/app/src/main/assets/public`。
- 卡点已确认：`npx cap build android` 因 `JAVA_HOME is not set and no 'java'` 失败——本沙箱无法编译二进制 APK。
- 交付两件让用户在本地/云端编译的东西：
  - `BUILD.md`：方式一 Android Studio 本地（Generate Signed APK）；方式二 GitHub Actions 云端。
  - `.github/workflows/build-apk.yml`：setup-java17 + android-actions/setup-android + `npx cap sync` + `./gradlew assembleDebug` + 上传 app-debug.apk 产物。
- 注：`cap add/sync` 在本环境会报 genie-safe-delete(trash) 错误，但工程仍正确生成；`cordova.js`/`cordova_plugins.js` 是 Capacitor 标准资源，无害。
- 改完 Web 后重新同步命令：`npx cap sync android`。
