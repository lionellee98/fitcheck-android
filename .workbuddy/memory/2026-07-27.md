## 修复：覆盖安装仍是旧版（签名不一致根因）
- 用户反馈：下载安装最新版后仍是旧版。经查 `latest` release 已指向最新 commit（fa39676 那版：5 动作 + 照片分析），链接没错。
- 根因：GitHub Actions 每次是全新临时 VM，默认 `debug.keystore` 随机生成 → 每次 APK 签名不同。手机上旧版用密钥 A 签、新版用密钥 B 签，覆盖安装时系统因**签名不一致直接拒绝**，用户以为装上了其实还是旧的。
- 修复：提交**固定 debug.keystore**（`android/app/debug.keystore`，密码 android/android，storepass/androiddebugkey）,由一次性 workflow `gen-keystore.yml` 用 keytool 生成并 git commit 回仓库；`.gitattributes` 标记 binary 防 CRLF 损坏。
- CI（`build-apk.yml`）新增两步：① cap sync 前用 `patch_index_version.py` 把 `index.html` 的 `<meta app-version>` 改成 `1.0.<run_number>`；② cap sync 后 `patch_gradle.py` 注入 `signingConfigs.debug`(幂等) 并把 `versionCode/versionName` 按 `github.run_number` 自增（每次真实升级，安装器当升级处理）。
- 身体情况页加「版本 vX」显示（`#appVersion` 读 meta），让用户一眼确认装的是新版。
- 关键经验：本地无 JDK/SDK，不能在沙箱生成 keytool；改为一次性 CI workflow 生成并 commit 回仓库。GitHub Actions 日志/artifact 的下载 URL 是跨域 blob 重定向，curl 跟随时**不能**带 Authorization（否则 403），且 `/tmp` 在此沙箱不可写，要写到工作区绝对路径。
- 因 gen-keystore workflow 自行 commit 把 main 往前推，导致后续 push 非快进；用 `git fetch origin main:refs/heads/origin-main` + `git merge origin-main` 合并（保留 keystore commit）再 push 解决；不要强行 rebase（会搞乱 working tree）。
- 已合并 commit 57eae23 并 push，触发 build run `30243542195` 成功（versionCode=13 → v1.0.13），latest release 已更新 APK。

## 跟练体验全面升级（commit 601634e → build 30250500843 success）
- 用户一次性提了 7 项：①开始跟练偶发消失根因 ②分类总耗时 ③跟练页放大图+横版钟表 ④间歇休息自动计算 ⑤完整语音播报 ⑥时间计算修复 ⑦照片分析"Invalid architecture Lightning"修复+保留手动勾选。
- **照片分析崩溃根因（已实证）**：装 `@tensorflow-models/pose-detection@2.1.3` 到 `.tmp_probe` 查源码，`validateModelConfig` 的 `VALID_MODELS=['SinglePose.Lightning','SinglePose.Thunder','MultiPose.Lightning']`，旧代码 `modelType:'Lightning'` 不在其中→抛错。改 `modelType: poseDetection.movenetModelType.LIGHTNING`（`?.` 兜底 `'SinglePose.Lightning'`）。模型本身没坏，无需改 fetch_movenet.js。手动勾选部位(concernChips)原本就在，作为备选保留。

- **按钮消失根因兜底**：`getActivePlan()`（currentPlan→草稿→已完成记录 三级兜底）用于 startWorkout/renderPlanResult；`resetPlanToPreview` 同时清 `#planResult` 防陈旧按钮；新增 `visibilitychange`/`pageshow` 监听，回到前台且停在计划页时 `renderPlan()` 重建（解决 WebView 被回收/重建导致的状态丢失）。
